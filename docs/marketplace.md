# Marketplace delivery

All listings use **Dagio.ai** as publisher label and **MIT** as their template licence. Actual
publication authority comes from the admitted Dagio.ai publisher account, never from a label.
The catalogue holds complete native listing metadata, with `alpha` maturity until actual
qualification justifies a different stage. Do not claim PMI affiliation or reproduce protected forms.

1. Edit/capture the native definition, bump its version and update its collection.
2. Run formatting, syntax, catalogue tests, verification and deterministic build.
3. Qualify the exact built catalogue with the Core's canonical schemas, template admission and
   instantiation. Retain the matching receipt under ignored `outputs/`.
4. Commit the source. Pack the same qualified content, retaining MIT and exact hashes.
5. Submit through the existing Surface Marketplace publication owner. Surface definitions use
   Surface Template publication; Spaces and Workflows use native Space Template publication.
   Observe current source/version, publisher, entitlement and review checks.
6. Qualify discovery and ordinary use in Development/Staging before approved Production publication.
   Do not substitute a GitHub release or successful repository build for Marketplace acceptance.

The user-facing entry is **Use this template** in the existing Marketplace chooser. Data/Workflow
Space templates create an independent native Space. Applying steps/resources to an existing
project requires the native preview/import operation described in the architecture; it must not
overwrite the current Scope. Do not mislabel Data/Workflow JSON as the historical `.space` archive
format, whose supported profiles belong to the Core importer.

Installation consent remains with the native owner when required. Selecting a template never
grants access to private source data, sends communications, authorizes purchases or marks project
work complete. Catalogue publication contains definitions and original content, never tenant data.
